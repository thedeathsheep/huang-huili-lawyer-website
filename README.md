# 黄绘莉律师个人网站

这是一个无需安装依赖、无需构建工具即可运行的响应式静态网站。所有样式、脚本和本地视觉资产均保存在项目内，没有第三方 CDN、字体、统计代码或图片热链。当前三张媒体 SVG 使用中性建筑、室内空间与自然光影作为临时视觉，不包含人物，也不代表黄绘莉律师本人或其真实办公环境。

## 文件结构

```text
黄绘莉律师个人网站/
├─ index.html                    页面内容、SEO 与结构化数据
├─ styles.css                   响应式视觉样式
├─ script.js                    移动导航、案例、滚动与 FAQ 交互
├─ robots.txt                   搜索引擎抓取基础规则
├─ README.md                    使用与上线说明
└─ assets/
   ├─ hero-placeholder.svg      首页中性建筑立面光影视觉
   ├─ profile-placeholder.svg   简介区石材、玻璃与纸张近景
   ├─ consultation-placeholder.svg  空置会议空间视觉
   ├─ qr-placeholder.svg        预留二维码文件（当前页面不展示）
   ├─ favicon.svg               浏览器图标
   └─ og-cover.svg              社交分享封面
```

## 打开网站

可以直接双击 `index.html` 预览。建议使用本地服务器，以便按照接近正式部署的方式检查：

```powershell
python -m http.server 8080 --directory "C:\Users\whatk\Downloads\黄绘莉律师个人网站"
```

然后访问：

```text
http://localhost:8080/
```

## 替换正式图片

当前 `hero-placeholder.svg`、`profile-placeholder.svg` 和 `consultation-placeholder.svg` 是中性建筑与空间光影视觉，仅用于版式和色彩占位，不是律师照片，不应被理解为律师本人、真实律所或真实案件场景。真实照片完成拍摄、取得使用授权并完成必要审核后，可以采用以下两种方式之一替换。

### 方法一：保持原文件名

将处理好的图片导出为对应名称并覆盖当前文件。若使用 JPG、PNG 或 WebP，需要同时修改 `index.html` 中对应图片的扩展名；若继续使用 SVG，则保留现有引用即可。

### 方法二：使用新的文件名

将图片放入 `assets`，然后在 `index.html` 搜索并修改对应文件路径：

| 用途 | 当前文件 | 当前 SVG 尺寸 | 正式素材推荐尺寸 | 构图要求 |
|---|---|---:|---:|---|
| 首页主视觉 | `assets/hero-placeholder.svg` | 1200×1500 | 1920×2400 或同等 4:5 竖版 | 真实人物素材到位后，人物可居中偏右，头部和肩部保留安全区 |
| 关于律师 | `assets/profile-placeholder.svg` | 1000×1250 | 1600×2000 或同等 4:5 竖版 | 真实人物素材到位后，可采用半身站姿与浅灰或真实律所背景 |
| 咨询场景 | `assets/consultation-placeholder.svg` | 1600×1000 | 1600×1000 | 横版，主体与桌面边缘保留裁切安全区，不展示可读案件材料 |
| 微信二维码 | `assets/qr-placeholder.svg` | 800×800 | 800×800 | 使用真实有效的正方形原图，四周保留足够静区并实机测试 |
| 浏览器图标 | `assets/favicon.svg` | 64×64 | 64×64 | 保持轮廓简洁，并检查 16×16 显示效果 |
| 分享封面 | `assets/og-cover.svg` | 1200×630 | 1200×630 | 可后续改为 JPG/PNG，并同步修改 `og:image` 路径与类型 |

当前三张中性视觉仅作装饰，页面使用空 `alt=""`，身份和业务信息均由相邻文字完整表达。只有真实律师照片已经到位并实际替换后，才应把对应图片的 `alt` 改为准确的人物描述，例如“黄绘莉律师职业半身照”；不能在尚未使用本人照片时写人物身份类替代文本。

页面当前不展示假二维码。`assets/qr-placeholder.svg` 仅作为预留文件保留，不应接入页面；收到真实、可扫描且确认指向正确联系方式的二维码后，再修改页面完成接入。

推荐正式照片优先使用 WebP 或高质量 JPEG，单张尽量控制在 300KB 以内；分享封面建议使用 JPG 或 PNG，因为部分社交平台不读取 SVG。

## 正式上线前必须复核

1. **执业信息**：姓名、执业证号、律所全称、地址和电话须由律师本人逐项确认。
2. **案例资料**：五个案例须确认均为真实承办或参与案件，并再次检查脱敏程度与发布授权。
3. **宣传文案**：建议由律师本人及律所按照当前适用的律师业务推广规范进行最终审核。
4. **人物图片与替代文本**：确认照片已获授权、确为本人且裁切正常后，再使用人物身份类 `alt`；中性空间图不得标注为律师照片。
5. **二维码**：保持页面不展示假二维码；真实二维码到位后再接入，并用多台设备测试扫描结果、目标账号和有效期。
6. **域名与备案**：确定域名后补充 canonical、正式 Open Graph 地址、ICP备案号；按实际部署情况办理相关备案。
7. **隐私政策**：当前网站没有表单、统计、在线客服或第三方地图，不主动收集访问者信息。未来如增加此类功能，应同步增加隐私政策、明示同意和相应安全措施。
8. **普法文章**：栏目目前明确标注“筹备中”，正式发布时需制作文章正文或独立详情页。
9. **分享封面**：检查 1200×630 尺寸、文字安全区和平台预览；域名确定后，将 `og:image` 改为可公开访问的绝对 URL。
10. **本地资源与兼容性**：确认所有图片、图标和脚本均能从生产路径加载，并在主流桌面与移动浏览器复核布局、对比度和焦点状态。

## 部署建议

整个目录可以直接上传到静态服务器、对象存储静态网站、GitHub Pages、Cloudflare Pages、Netlify 或常规虚拟主机。若部署在中国大陆服务器，请先确认域名与备案要求。

域名确定后建议另行生成：

- `sitemap.xml`
- 正式 canonical URL
- 绝对地址的 Open Graph 图片
- 生产环境安全响应头
- 404 页面

## 浏览器支持

推荐最新版 Chrome、Edge、Firefox 和 Safari。页面使用渐进增强：即使 JavaScript 被禁用，主要内容、FAQ 和案例文字仍可阅读；移动菜单和案例折叠等增强交互需要 JavaScript。
